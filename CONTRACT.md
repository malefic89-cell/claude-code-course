# CONTRACT.md — границы между слоями

Что в проекте можно менять независимо и что нельзя обходить. Правила
разработки — в CLAUDE.md, план — в PLAN.md. Этот файл — про то, чего
интерфейс, контент и хранилище друг от друга ждут. Точные типы и сигнатуры
живут в коде и здесь не дублируются.

## Три слоя

| Слой | Владелец | Код |
|---|---|---|
| Контент курса | автор курса | `content/`, читается через `lib/content.ts` |
| Прогресс пользователя | `lib/progress.ts` | хранилище (сейчас localStorage) |
| Интерфейс | `app/`, `components/` | строки — только из `lib/i18n.ts` |

Интерфейс знает о контенте и прогрессе только через экспорты этих трёх
файлов. Контент и прогресс об интерфейсе не знают ничего.

## Контент

- **Модуль** — `content/modules/module-MM.json`: `id`, `title`,
  `description`, `icon`, `tasks` (id задач в порядке прохождения).
  Порядок задач задаёт этот список, а не номера в id.
- **Задача** — `content/tasks/task-MM-NN.md`: frontmatter (`id`, `module`,
  `title`, `difficulty`, `estimated_minutes`, `verified_date`) и Markdown-тело
  с разделами `## Цель`, `## Инструкция (пошагово)`, `## Критерий выполнения`,
  `## Подсказки` (опционально). Интерфейс рендерит тело как есть и может
  особо оформлять эти четыре заголовка, но не зависит от других.
- **Id задачи стабилен навсегда.** По нему хранится прогресс пользователя.
  Переименовать задачу можно, поменять id — нет (это потеря прогресса у всех,
  кто её отметил). Удалённая задача просто исчезает из списка модуля; её id
  в хранилище никому не мешает.
- **Правка текстов не требует кода.** Если для контентной правки пришлось
  трогать `app/` или `components/` — это нарушение контракта, а не фича.
- Иконка модуля — имя из `components/ModuleIcon`. Новая иконка = правка
  кода, это допустимо; неизвестное имя рисуется заглушкой, а не ошибкой.
- Некорректный frontmatter или JSON модуля — ошибка сборки, не тихий пропуск.
  Сюда же: `module` задачи должен совпадать с модулем, в списке которого она есть.

## Прогресс

- Единственная точка работы с хранилищем — `lib/progress.ts`. Компоненты не
  обращаются к `localStorage` (и к любому будущему хранилищу) напрямую.
- Прогресс — множество id выполненных задач. Ничего больше: ни времени,
  ни попыток, ни ответов. Расширение формата — изменение контракта.
- В компонентах прогресс читается через `useDoneSet`, меняется через
  `markDone` / `unmarkDone`. На сервере и при гидратации прогресс пустой —
  интерфейс обязан корректно выглядеть в этом состоянии.
- Замена localStorage на сервер (этап 6) меняет только реализацию
  `lib/progress.ts`; экспортируемые функции и `useDoneSet` остаются.
- Настройки оформления (тема) — не прогресс. Они хранятся отдельно, через
  `lib/theme.ts`, и на сервер не переезжают.

## Интерфейс

- Все видимые строки — из словаря `lib/i18n.ts`. Новый текст = новая запись
  в словаре, не литерал в JSX. Так остаётся возможна локализация.
- Компоненты маленькие, типизированные, без `any`; новая библиотека — только
  после вопроса «нельзя ли без неё».
- Интерфейс может свободно: добавлять и переделывать компоненты и страницы,
  анимации, тему, иконки, строки словаря. Это не затрагивает контракт.
- Мобильная ширина от 360px обязательна для каждого экрана.

## Как менять контракт

Изменение любого пункта выше — отдельный коммит, в котором обновляются
вместе этот файл и код (`lib/content.ts`, `lib/progress.ts` или
`lib/i18n.ts`). Редизайн (этап 5) контракт не меняет: если в ходе редизайна
захотелось его изменить — сначала обсуждение, потом отдельный коммит.

## Цель

Научиться возвращать файлы к последнему коммиту, когда правка Claude оказалась неудачной.

## Инструкция (пошагово)

Это задача, ради которой был весь блок. Если после правки Claude проект перестал работать, а разбираться в причинах не хочется, самый быстрый путь — вернуть файлы к последней сохранённой точке и попросить заново, иначе.

1. Продолжайте в проекте из задачи 00-04. Убедитесь, что `git status` показывает `working tree clean`: последняя точка сохранена, есть куда откатываться.
2. Сломайте файл нарочно: откройте `README.md` в редакторе, удалите всё содержимое, оставьте одну строку `Сломано` и сохраните.
3. Вернитесь в терминал: `git diff` покажет много строк с `-` — весь прежний текст удалён. Представьте, что это была важная документация или рабочий код, и что сделал это не вы, а Claude по неудачно сформулированной просьбе.

   ![git diff после ломающей правки: весь прежний текст красным с минусом, одна зелёная строка](/screenshots/00-05-broken-diff.png)
4. Верните всё как было:
   ```bash
   git restore .
   ```
   Точка в конце означает «все файлы в проекте». Команда ничего не выводит.
5. Проверьте: `git status` снова `working tree clean`, а в `README.md` прежний текст. Ломающая правка исчезла бесследно, история коммитов не тронута.

   ![git restore . вернул файл: git status снова working tree clean](/screenshots/00-05-restore.png)
6. Повторите шаги 2–5 ещё раз с любой другой правкой, чтобы движение «сломал — откатил» стало привычным. С модуля 1 откат можно будет попросить и у Claude Code: «откати все изменения к последнему коммиту».

## Критерий выполнения

Задача выполнена, если после «ломающей» правки вы вернули файлы к последнему коммиту, и `git status` показывает `working tree clean`, а содержимое `README.md` прежнее.

## Подсказки

- `git restore .` отменяет изменения только в файлах, которые уже были в истории. Новые файлы останутся — они видны в `git status` как `Untracked`, их можно просто удалить.
- В модуле 3 встретится команда `git reset --hard HEAD` — она делает то же самое и чуть больше, поэтому там она сопровождается предупреждением. Для повседневного отката хватает `git restore .`.
- Откат необратим: то, что не было закоммичено, пропадает. Поэтому правило из прошлой задачи — коммит после каждого удачного шага — и есть то, что делает откат безопасным.
- Если правка понравилась лишь частично, откатывать всё не обязательно: `git restore имя-файла` вернёт один файл, остальные останутся.

## Цель

Задать отдельные правила для части проекта через CLAUDE.md в подпапке и увидеть, что их видят и субагенты.

## Инструкция (пошагово)

Пока «Полка» была одной папкой, хватало одного CLAUDE.md. С экспортом из 05-02 появились данные, и для них удобны свои правила.

1. Попросите Claude вынести стартовые карточки из кода в файл `data/cards.json` и загружать их оттуда. Подтвердите правки.
2. Создайте `data/CLAUDE.md` из терминала, как в 02-06: `notepad data\CLAUDE.md` (macOS: `touch data/CLAUDE.md`, затем `open -e data/CLAUDE.md`), на вопрос о создании файла ответьте «Да». Впишите правило, отличное от корневого, например: «Файлы в этой папке — только данные. Никакого кода и комментариев, ключи объектов на английском в camelCase». Сохраните (Ctrl+S) и проверьте имя: `ls data` должен показать ровно `CLAUDE.md`. Если получилось `CLAUDE.md.txt` — переименуйте: `mv data\CLAUDE.md.txt data\CLAUDE.md` (ловушка из 00-01: окно «Сохранить как» добавляет `.txt`, если не выбрать «Все файлы»).
3. Перезапустите `claude`. Попросите добавить в `data/cards.json` одну карточку — правило из подпапки должно проявиться в diff (ключи, формат).

   ![Правка data/cards.json по правилу из data/CLAUDE.md: только данные, ключи на английском](/screenshots/05-04-nested-rule.png)
4. Попросите то же через субагента: «поручи субагенту добавить ещё одну карточку в data/cards.json». Правило действует и для него: вложенные CLAUDE.md читаются по расположению файла, а не по тому, кто его правит.
5. Выполните `/memory` и найдите оба файла в списке.

## Критерий выполнения

Задача выполнена, если правка в `data/` следует правилу из `data/CLAUDE.md`, а корневые правила при этом не сломались.

## Подсказки

- Вложенные файлы нужны не всем: на маленьком проекте хватает одного. Смысл появляется, когда части проекта живут по разным правилам.
- Если правило не сработало — проверьте, что файл лежит именно в `data/` и назван `CLAUDE.md` с большими буквами, и что сессия перезапущена.

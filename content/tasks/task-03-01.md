## Цель

Увидеть на собственном опыте, что происходит, когда крупную расплывчатую задачу дают без планирования.

## Инструкция (пошагово)

В этой задаче Claude нарочно наломает дров — значит, нужен способ всё вернуть. Это ровно то, чему учил модуль 0: коммит как точка возврата (00-04), `git diff` (00-03) и откат (00-05). Здесь откат делается командой `git reset --hard HEAD`: она возвращает все файлы к последнему коммиту. **Осторожно: она стирает все незакоммиченные изменения в проекте, восстановить их нельзя.** Именно поэтому сначала коммит, и только потом эксперимент.

1. Работайте в «Полке»: она под git, и всё, что сломается, вернётся откатом. Зафиксируйте состояние — две команды по очереди:
   ```bash
   git add -A
   git commit -m "Перед экспериментом"
   ```
2. В обычном режиме дайте нарочно крупную и расплывчатую задачу, без деталей, например:
   ```
   Добавь в «Полку» поиск, фильтры, сортировку и экспорт. Ничего не коммить.
   ```
   «Не коммить» здесь важно: если Claude сам сделает коммит, точка возврата из шага 1 перестанет быть последней, и откат в шаге 6 её не найдёт.
3. Наблюдайте за процессом: сколько файлов меняется, спрашивает ли Claude уточнения, совпадает ли результат с тем, что вы смутно имели в виду.
4. Посмотрите итог: `git diff --stat` покажет, сколько файлов задето и насколько, а `git diff` — сами изменения.

   ![git diff --stat после «сделай всё сразу»: три файла и 277 добавленных строк за один запрос](/screenshots/03-01-big-diff.png)
5. Ответьте себе на вопросы: смогли бы вы отревьюить всё это за раз? Там ли сделаны изменения, где вы ожидали? Что Claude понял не так?
6. Откатите эксперимент: `git reset --hard HEAD` (мы фиксировали состояние в шаге 1).

## Критерий выполнения

Задача выполнена, если вы можете назвать две конкретные проблемы подхода «всё сразу без плана» на примере того, что получилось у вас.

## Подсказки

- Типичные проблемы: Claude додумал требования по-своему; изменений слишком много для осмысленного ревью; задето то, что трогать не планировалось.
- Если Claude всё-таки закоммитил: `git log --oneline` покажет историю, найдите строку `Перед экспериментом` и откатитесь к ней по хэшу: `git reset --hard <хэш>`. Хэш — семь символов в начале строки.
- Дело не в том, что Claude «плохо справился» — дело в постановке. Расплывчатый запрос заставляет угадывать. Как ставить лучше — весь остальной модуль.

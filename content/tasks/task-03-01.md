## Цель

Увидеть на собственном опыте, что происходит, когда крупную расплывчатую задачу дают без планирования.

## Инструкция (пошагово)

1. Работайте в учебном проекте (не в важном коде!). Зафиксируйте состояние — две команды по очереди:
   ```bash
   git add -A
   git commit -m "before experiment"
   ```
2. В обычном режиме дайте нарочно крупную и расплывчатую задачу, например: «Добавь в проект систему настроек пользователя» — без деталей.
3. Наблюдайте за процессом: сколько файлов меняется, спрашивает ли Claude уточнения, совпадает ли результат с тем, что вы смутно имели в виду.
4. Посмотрите итог: `git diff` покажет весь объём изменений.
5. Ответьте себе на вопросы: смогли бы вы отревьюить всё это за раз? Там ли сделаны изменения, где вы ожидали? Что Claude понял не так?
6. Откатите эксперимент: `git reset --hard HEAD` (мы фиксировали состояние в шаге 1).

## Критерий выполнения

Задача выполнена, если вы можете назвать две конкретные проблемы подхода «всё сразу без плана» на примере того, что получилось у вас.

## Подсказки

- Типичные проблемы: Claude додумал требования по-своему; изменений слишком много для осмысленного ревью; задето то, что трогать не планировалось.
- Дело не в том, что Claude «плохо справился» — дело в постановке. Расплывчатый запрос заставляет угадывать. Как ставить лучше — весь остальной модуль.

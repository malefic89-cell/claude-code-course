## Цель

Научиться задавать отдельные правила для частей большого проекта через CLAUDE.md в подпапках.

## Инструкция (пошагово)

1. В учебном проекте создайте подпапку с парой файлов, например `frontend/` (или используйте существующую).
2. Создайте в ней файл `frontend/CLAUDE.md` с правилом, отличным от корневого, например: «Все компоненты в этой папке — только функциональные, со стрелочными функциями».
3. Запустите `claude` в корне проекта.
4. Попросите создать небольшой файл в подпапке: «Создай в frontend простой компонент кнопки».
5. Проверьте, соблюдено ли правило из вложенного файла.
6. Для контраста попросите создать файл в корне — правило подпапки на него распространяться не должно.

## Критерий выполнения

Задача выполнена, если правило из вложенного CLAUDE.md повлияло на работу в его папке, и вы можете объяснить, зачем нужны вложенные файлы.

## Подсказки

- Типичный случай: монорепозиторий, где `frontend/` и `backend/` живут по разным правилам.
- Вложенные файлы подхватываются, когда Claude работает с содержимым соответствующей папки. Точное поведение сверяйте с актуальной документацией — механизм развивается.
- Не заводите вложенные файлы «на всякий случай»: пока правила не различаются, достаточно корневого.

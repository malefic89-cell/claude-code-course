## Цель

Открыть pull request на GitHub, не выходя из терминала, и понять, что в нём видно.

## Инструкция (пошагово)

Pull request (PR) — предложение влить ветку в main. На GitHub у него есть описание, diff, обсуждение и кнопка слияния. Даже в личном проекте PR полезен: это место, где фичу видно целиком.

1. В ветке `feature/tags` попросите Claude:
   ```
   Открой pull request в main для этой ветки. В описании: что сделано, как проверить.
   ```
2. Claude соберёт описание по коммитам и вызовет `gh pr create` — разрешите. В ответе будет ссылка на PR.
3. Откройте PR в браузере (`gh pr view --web`). Прочитайте описание и посмотрите вкладку Files changed — это тот же diff, что вы читали в терминале, но целиком по фиче.
4. Сравните описание с тем, что вы бы написали сами. Если Claude что-то приписал или пропустил — поправьте текст прямо на GitHub или попросите Claude обновить PR.
5. PR пока не вливайте: ревью в следующей задаче.

## Критерий выполнения

Задача выполнена, если PR открыт, его описание соответствует сделанному, и вы знаете, где смотреть diff всей фичи.

## Подсказки

- PR можно открыть и кнопкой на GitHub. Через `gh` быстрее и описание пишет Claude, но проверять его — вам.
- Один PR — одна фича. Если в ветке накопилось два несвязанных изменения, лучше две ветки и два PR.

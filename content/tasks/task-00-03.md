## Цель

Научиться проверять, что именно Claude поменял в файлах, двумя командами: `git status` и `git diff`.

## Инструкция (пошагово)

Claude Code показывает правки в момент, когда их делает, но после нескольких запросов легко потерять нить: что изменилось за всю сессию? Git отвечает на этот вопрос точно, потому что сравнивает файлы с последним сохранённым состоянием.

Для этой задачи нужен репозиторий, где уже есть хотя бы один коммит, — подойдёт проект, склонированный в задаче 00-02.

1. Перейдите в папку склонированного проекта и убедитесь, что она чистая: `git status` показывает `working tree clean`.
2. Внесите небольшую правку руками: откройте `README.md` в редакторе (`notepad README.md` на Windows, `open -e README.md` на macOS), добавьте в самое начало строку `Учебная копия` и сохраните. В модуле 1 такие правки будет делать Claude Code, а проверять их вы будете точно так же.
3. Вернитесь в терминал и выполните:
   ```bash
   git status
   ```
   Теперь файл `README.md` в списке `Changes not staged for commit` — git заметил, что он отличается от сохранённого.

   ![README.md изменён: git status показывает его в Changes not staged for commit](/screenshots/00-03-git-status.png)
4. Посмотрите, что именно изменилось:
   ```bash
   git diff
   ```
   **Diff** — это разница между двумя версиями файла построчно. Строки с `+` в начале добавлены, строки с `-` удалены, остальные показаны для контекста. Выход из просмотра — клавиша `q`.

   ![git diff: одна зелёная строка с плюсом — ваша правка, остальное контекст](/screenshots/00-03-git-diff.png)
5. Сверьте diff с тем, что вы сделали. Ожидание: одна добавленная строка, ничего лишнего. Когда файлы начнёт править Claude, этот же экран покажет, не тронул ли он что-то сверх просьбы, — ради этого и нужен diff.

## Критерий выполнения

Задача выполнена, если `git status` показывает изменённый файл, а в выводе `git diff` вы можете указать добавленную строку.

## Подсказки

- **В diff есть строки, которых вы не трогали** (`\_` вместо `_`, лишняя пустая строка в конце) — это Блокнот Windows 11: он открывает `.md` в форматированном виде и при сохранении переписывает файл по-своему. Верните файл (`git restore README.md`), откройте снова и до правки переключите меню «Просмотр» → «Markdown» → «Синтаксис» (в старых версиях меню называется «Вид»). Кстати, вы только что увидели, зачем нужен diff: он ловит и такие правки.
- Если `git diff` ничего не показывает — проверьте, что файл сохранён, и что вы правили именно `README.md` в папке проекта, а не создали новый файл. Новые файлы `git diff` не показывает, их видно в `git status` как `Untracked`.
- С модуля 1 diff можно будет спросить и у Claude Code: «покажи git diff». Но полезно уметь самому — так вы проверяете Claude, а не Claude проверяет себя.
- Diff одного файла: `git diff README.md`.

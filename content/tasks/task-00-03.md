## Цель

Научиться проверять, что именно Claude поменял в файлах, двумя командами: `git status` и `git diff`.

## Инструкция (пошагово)

Claude Code показывает правки в момент, когда их делает, но после нескольких запросов легко потерять нить: что изменилось за всю сессию? Git отвечает на этот вопрос точно, потому что сравнивает файлы с последним сохранённым состоянием.

Для этой задачи нужен репозиторий, где уже есть хотя бы один коммит, — подойдёт проект, склонированный в задаче 00-02.

1. Перейдите в папку склонированного проекта и убедитесь, что она чистая: `git status` показывает `working tree clean`.
2. Запустите `claude` и попросите небольшую правку, например: «В файле README.md добавь в самом начале строку "Учебная копия" и больше ничего не меняй». Подтвердите правку, когда Claude её предложит.
3. Выйдите из Claude и выполните:
   ```bash
   git status
   ```
   Теперь файл `README.md` в списке `Changes not staged for commit` — git заметил, что он отличается от сохранённого.
4. Посмотрите, что именно изменилось:
   ```bash
   git diff
   ```
   **Diff** — это разница между двумя версиями файла построчно. Строки с `+` в начале добавлены, строки с `-` удалены, остальные показаны для контекста. Выход из просмотра — клавиша `q`.
5. Сверьте diff с тем, что вы просили. Ожидание: одна добавленная строка, ничего лишнего. Если Claude изменил что-то ещё, вы это увидели, — ради этого и нужен diff.

## Критерий выполнения

Задача выполнена, если `git status` показывает изменённый файл, а в выводе `git diff` вы можете указать добавленную строку.

## Подсказки

- Если `git diff` ничего не показывает, хотя Claude отчитался о правке, — возможно, он создал новый файл, а не изменил старый. Новые файлы `git diff` не показывает, их видно в `git status` как `Untracked`.
- Правку можно посмотреть и не выходя из Claude: попросите его «покажи git diff». Он выполнит команду за вас. Но полезно уметь и самому — так вы проверяете Claude, а не Claude проверяет себя.
- Diff одного файла: `git diff README.md`.

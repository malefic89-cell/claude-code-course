## Цель

Добавить в CLAUDE.md рабочие разделы — стек, команды, правила кода — и убедиться, что правила реально влияют на поведение Claude.

## Инструкция (пошагово)

1. Дополните CLAUDE.md «Полки» тремя разделами (если их ещё нет):
   - **Технический стек** — «HTML, CSS и JavaScript без сборки и без библиотек; страница открывается двойным кликом по index.html»;
   - **Команды** — сборки и тестов нет; проверка — открыть index.html в браузере; сохранить — `git add -A`, `git commit -m "..."`;
   - **Правила кода** — 3–5 конкретных правил, например: данные карточек хранятся в localStorage; обложка по умолчанию — эмодзи; новые библиотеки не подключать; все комментарии в коде — на русском.
2. Одно правило сделайте **легко проверяемым**, например: «Все комментарии в коде — на русском языке».
3. Перезапустите сессию `claude`.
4. Попросите, не напоминая о правиле:
   ```
   Создай app.js, подключи его к index.html и добавь функцию, которая считает карточки на полке, с комментарием
   ```
5. Проверьте: соблюдено ли правило из файла?

   ![Правило сработало: комментарии в новом app.js на русском, хотя в запросе о языке ни слова](/screenshots/02-04-rule-applied.png)

## Критерий выполнения

Задача выполнена, если Claude выполнил ваше правило, хотя в самом запросе вы о нём не упоминали.

## Подсказки

- Правила формулируйте конкретно. «Пиши чистый код» не работает; «не использовать any в TypeScript» — работает.
- Если правило не сработало: проверьте, что сессия перезапущена после правки файла, и что правило сформулировано однозначно.

## Цель

Пройти путь одной правки от терминала до обновлённого сайта и увидеть, где смотреть статус деплоя.

## Инструкция (пошагово)

1. Придумайте видимую правку: название полки, подпись под заголовком, порядок стартовых карточек. Ветка, правка через Claude, коммит, PR, слияние — весь цикл по памяти.
2. Сразу после слияния посмотрите статус деплоя:
   ```bash
   gh run list --limit 3
   ```
   Первая строка — деплой Pages: в работе или завершён. Или вкладка Actions на GitHub.
3. Когда деплой завершился, обновите сайт в браузере. Правка на месте. Если нет — жёсткое обновление (Ctrl+F5): браузер мог показать старую копию.
4. Попросите Claude сверить: «открой сайт и проверь, что заголовок теперь такой-то». Это последняя проверка через браузер в курсе.
5. Отправьте ссылку кому-нибудь. Это и есть результат курса: продукт, который вы сделали вместе с Claude, по ссылке.

## Критерий выполнения

Задача выполнена, если правка видна на опубликованном сайте, и вы знаете, где смотреть статус деплоя.

## Подсказки

- Между слиянием и обновлением сайта проходит от 20 секунд до пары минут. Если через пять минут ничего — смотрите ошибку в Actions.
- Ссылку на сайт стоит положить и в описание репозитория: `gh repo edit --homepage <адрес>`.

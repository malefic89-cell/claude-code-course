## Цель

Почувствовать цену субагентов и выработать правило, когда они не нужны.

## Инструкция (пошагово)

1. Дайте маленькую задачу двумя способами и засеките время. Сначала напрямую:
   ```
   Поменяй в заголовке «Полки» слово «Коллекция» на «Моя коллекция»
   ```
   Откатите: `git restore .`.
2. Теперь то же самое через субагента:
   ```
   Поручи субагенту поменять в заголовке «Полки» слово «Коллекция» на «Моя коллекция»
   ```
   Откатите снова.
3. Сравните: время, число шагов, сколько раз спрашивали разрешение. Второй способ дольше и не дал ничего взамен.
4. Выпишите для себя три случая, когда субагент оправдан, и три, когда нет. Сверьте с подсказками.

## Критерий выполнения

Задача выполнена, если вы можете объяснить на своём примере, почему субагент для правки одной строки — лишняя работа.

## Подсказки

- Оправдан: большое чтение, результат которого нужен коротко; независимые части параллельно; долгая проверка в фоне.
- Не оправдан: правка в одном месте; задача, где вы хотите видеть каждый шаг; всё, что требует ваших ответов по ходу.
- Субагент стоит токенов: у него свой контекст, свой старт. На подписке это время, на API — деньги.

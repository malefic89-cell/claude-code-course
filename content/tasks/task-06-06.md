## Цель

Создать конфликт слияния нарочно и разобрать его вместе с Claude, понимая каждый шаг.

## Инструкция (пошагово)

1. Создайте две ветки от main: `feature/title-a` и `feature/title-b` (команды — в шпаргалке 06-00; перед созданием второй вернитесь в main). В каждой попросите Claude по-разному изменить заголовок «Полки» в `index.html` и закоммитить. Обе ветки отправьте на GitHub.
2. Откройте PR для первой и влейте его (06-03, 06-05).
3. Откройте PR для второй. GitHub покажет: «This branch has conflicts». Не нажимайте кнопки разрешения на сайте — разберём в терминале.
4. В ветке `feature/title-b` попросите Claude:
   ```
   Подтяни main в эту ветку и покажи конфликт, не разрешая его
   ```
   Claude выполнит `git merge main`, и в `index.html` появятся маркеры `<<<<<<<`, `=======`, `>>>>>>>`. Откройте файл и прочитайте: между маркерами — две версии одной строки.

   ![index.html в Блокноте с маркерами конфликта: две версии заголовка между <<<<<<< и >>>>>>>](/screenshots/06-06-markers.png)
5. Решите сами, какой заголовок правильный (или объедините), и скажите Claude. Он уберёт маркеры, вы подтвердите diff, затем коммит слияния и `git push`.
6. PR на GitHub стал зелёным — влейте его.

## Критерий выполнения

Задача выполнена, если вы видели маркеры конфликта в файле, выбрали версию сами, и оба PR влиты в main.

## Подсказки

- Конфликт — не ошибка, а вопрос: git не знает, какая версия нужна, и спрашивает. Отвечать должны вы, не Claude: он не знает, что вы хотели.
- Если запутались: `git merge --abort` возвращает ветку в состояние до слияния, можно начать заново.
- Если git не даёт переключить ветку из-за незакоммиченных правок — отложите их: `git stash`, переключитесь, потом `git stash pop` (шпаргалка 06-00).

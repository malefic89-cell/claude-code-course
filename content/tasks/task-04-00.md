## Цель

Понять, что умеет Claude Code без внешних инструментов и чего не умеет, и увидеть эту границу на своей «Полке».

## Инструкция (пошагово)

До сих пор Claude работал с тем, что лежит в папке: читал и правил файлы, запускал команды. Но «Полка» живёт в браузере, и проверить, как она выглядит и работает, Claude пока не может — это делали вы, руками, в задачах 03-07 и 03-09. MCP (Model Context Protocol) — способ дать Claude доступ к внешним инструментам: браузеру, базе данных, GitHub. Такой инструмент называется MCP-сервером.

1. Запустите `claude` в «Полке» и попросите:
   ```
   Открой index.html в браузере и проверь, что поиск по названию работает
   ```
2. Прочитайте ответ. Claude попробует дотянуться до браузера и честно сообщит, что не может: расширение Claude in Chrome не подключено. Дальше он «проверит» поиск по коду, не запуская страницу. Обратите внимание на эту оговорку — это и есть граница.

   ![Без расширения браузер недоступен: Claude сообщает об этом и проверяет поиск по коду, а не на экране](/screenshots/04-00-no-browser.png)
3. Спросите Claude, какие инструменты у него сейчас есть:
   ```
   Какие инструменты тебе доступны в этой сессии? Перечисли коротко
   ```
4. Выполните `/mcp`. В списке уже есть встроенный сервер `claude-in-chrome` — Claude Code поставляется с ним, но работать он начнёт только после установки расширения в Chrome. Этим займётся следующая задача.
5. Сформулируйте для себя, какая проверка «Полки» стала бы проще, если бы Claude видел страницу в браузере.

## Критерий выполнения

Задача выполнена, если вы можете объяснить одной фразой, чего Claude не может без подключённого браузера, и видели в `/mcp` встроенный сервер `claude-in-chrome`.

## Подсказки

- MCP — открытый протокол, серверы пишут разные компании и сообщество. Claude Code — клиент, который к ним подключается; браузерный сервер у него встроен, остальные подключаются командой `claude mcp add`.
- Всё, что Claude делает через MCP, тоже проходит через разрешения: как с правкой файлов в 01-06.

# CLAUDE.md — Обучающее приложение «Claude Code Course»

## О проекте

Веб-приложение для обучения работе в Claude Code через практические задачи.
Формат вдохновлён self-paced курсами: модули → задачи → чек-листы → трекер прогресса.
Принципы:
- **80% практики** — каждая задача выполняется пользователем в реальном терминале с Claude Code, приложение даёт инструкцию и проверяет результат.
- **Удержание** — аудитория приходит добровольно и легко уходит: короткие задачи, видимый результат, живой интерфейс. Предмет курса при этом не меняется — это курс по Claude Code, а не по «вайбкодингу вообще».

**Аудитория (по приоритету):**
1. Внешние пользователи — любой человек, который хочет освоить Claude Code (основной потребитель). Опыт с git и терминалом не гарантирован: всё необходимое объясняется на месте, как уже сделано по итогам пилота.
2. Сотрудники IT-лаборатории
3. Ученики школы

**Язык интерфейса:** русский (архитектура должна допускать i18n в будущем — все строки UI выносить в словари, не хардкодить).

## Технический стек

- **Next.js 14+ (App Router), TypeScript, React**
- **Tailwind CSS** для стилей
- **Хранение прогресса:** localStorage в MVP (обёрнуто в отдельный модуль `lib/progress.ts`, чтобы позже заменить на серверную БД без переписывания компонентов)
- **Контент курса:** Markdown/JSON-файлы в `/content` — редактируются без деплоя кода
- Без авторизации в MVP. Без внешних БД в MVP.

## Структура проекта

```
/app                — маршруты Next.js (App Router)
  /layout.tsx       — шапка, переключатель темы, левая рейка «Карта курса»
  /page.tsx         — главная: заголовок, карточка прогресса, программа
  /module/[id]      — страница модуля с оглавлением задач
  /task/[id]        — страница задачи
/components         — UI-компоненты (ModuleCard, TaskList, TaskBody, TaskCompletion, CourseRail…)
/content
  /modules          — module-00.json, module-01.json… (метаданные модулей)
  /tasks            — task-00-00.md… (тексты задач в Markdown с frontmatter)
/lib
  /content.ts       — загрузка и парсинг контента
  /progress.ts      — API прогресса (единственная точка работы с хранилищем)
  /i18n.ts          — словарь строк интерфейса
  /theme.ts         — светлая/тёмная тема (хранится отдельно от прогресса)
/public             — статика
CONTRACT.md         — границы между контентом, прогрессом и интерфейсом
```

## Формат контента

Каждая задача — Markdown-файл с frontmatter:

```yaml
---
id: "01-03"
module: "01"
title: "Первый запуск Claude Code"
difficulty: easy | medium | hard
estimated_minutes: 10
---
## Цель
## Инструкция (пошагово)
## Критерий выполнения
«Задача выполнена, если…» — конкретный проверяемый результат.
## Подсказки (опционально, скрыты по умолчанию)
```

Модуль (JSON): id, title, description, icon, порядок задач.

## Программа курса

MVP — модули 0–3. Остальные добавляются позже, архитектура должна их поддерживать сразу.

0. **Git-минимум** — терминал и папки, репозиторий, clone, diff, коммит, откат: страховка для работы с Claude Code, без веток и push (добавлен для внешней аудитории)
1. **Основы CLI** — установка, первый запуск, базовые команды, режимы (MVP)
2. **CLAUDE.md** — контекст проекта, инструкции, память (MVP)
3. **Plan mode и итерации** — планирование, ревью, циклы (MVP)
4. MCP-серверы
5. Субагенты и параллельная работа
6. Git-интеграция

## Функциональность MVP

- Каталог модулей с прогрессом по каждому
- Страница задачи: цель, инструкция, чек-лист «критерий выполнения», кнопка «Выполнено»
- Общий трекер прогресса (X из Y задач, % по модулю)
- Раскрываемые подсказки в задачах
- Адаптивная вёрстка (ноутбук и телефон, ≥360px)

**Не делаем в MVP:** авторизацию, серверное хранение, AI-проверку ответов, английскую локализацию. Но код не должен блокировать их добавление.

**Геймификация:** стрики/бейджи/XP — под вопросом, решение за автором курса (агрессивная геймификация в стиле Duolingo раздражает часть аудитории). Ощущение прогресса — анимация отметки задачи, «модуль пройден», дорожка курса — делаем в рамках редизайна (этап 5).

## Правила разработки

- Границы между контентом, прогрессом и интерфейсом описаны в CONTRACT.md; редизайн их не меняет

- Работаем итеративно: сначала план (plan mode), затем реализация небольшими шагами с проверкой
- Каждая фича — отдельный коммит с осмысленным сообщением на английском (`feat:`, `fix:`, `content:`)
- Контентные правки (тексты задач) не должны требовать изменений кода
- Компоненты — маленькие и типизированные; никакого `any`
- Перед добавлением библиотеки — спросить, нельзя ли обойтись без неё
- Не изобретать содержание задач курса самостоятельно: тексты задач пишет/утверждает автор курса, Claude помогает со структурой и черновиками по запросу

## Команды

```bash
npm run dev      # локальная разработка
npm run build    # проверка сборки перед коммитом
npm run lint     # линтер — обязателен перед коммитом
```

## Дорожная карта (контекст для решений)

- **Этапы 1–3 (завершены):** контент модулей 1–3, каркас приложения, MVP UI, деплой
- **Этап 4 (частично):** пилот — тестер 1 (сотрудник) пройден, правки внесены; тестер 2 не начат
- **Этап 5 (текущий):** редизайн фронтенда и ощущение прогресса — для удержания внешней аудитории
- **Этап 6:** модули 4–6, геймификация (по решению автора), серверный прогресс, AI-проверка через Anthropic API, локализация

Детали и статусы — в PLAN.md.

## Риски (учитывать при проектировании)

- Claude Code быстро обновляется → контент версионировать, в frontmatter задач хранить `verified_date`, ревизия раз в квартал
- Разный уровень аудитории (внешние, сотрудники, школьники) → поле difficulty и подсказки обязательны с первой версии
- Добровольная внешняя аудитория легко уходит → интерфейс и ощущение прогресса — часть продукта, а не украшение; пилот тестера 1 показал, что даже IT-сотрудник спотыкался о git и PowerShell — для внешних это главная точка отвала
